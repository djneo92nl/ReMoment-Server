# Sticky player bar

A fixed bottom row on every web page (`resources/views/layouts/app.blade.php`) showing the player pinned in this browser. Pinning one makes it the default target of the library play buttons.

## Selected device
- Cookie `remoment_player` (device id, forever), read through `App\Support\SelectedDevice` (scoped singleton: one lookup per request; a cookie for a deleted device is ignored).
- `POST /player/select/{device}` (`player.select`) pins, `DELETE /player` (`player.clear`) unpins. Unauthenticated like the play routes; there are no accounts, so the pin is per browser.

## Panels
`PlayerBar::$panel` (`queue` | `players` | `multiroom` | null) opens a panel floating just above the bar's right side, in the bar's artwork colors (`livewire/partials/player-queue`, `player-picker`, `multiroom-content` with `inPanel`; mini-players use `glass`). The queue panel lists Up next and, with `queue_jump`, plays from a clicked track ; each row also gets move up / move down / remove (and is draggable with `queue_move`: Alpine `queueSort` on the `<ol>`, rows carry `data-pos`/`data-uri`, a drop calls `moveInQueue` with the dragged row's uri; the chevrons are the fallback; the same on the device page's Up Next card), refreshing at once on the MQTT `queue` ping, and the header a Clear button, gated by `queue_move` / `queue_remove` / `queue_clear` (`Livewire\Concerns\EditsQueue`; a refused edit shows as `$queueError`, and rows pass their uri as `expect`). The picker replaces the old modal and has a "No player" entry (`DELETE /player`). Clicking outside a panel closes it. The queue panel starts with the playing track; the queue icon only shows for a playing track (not radio/line-in). Space toggles play/pause (when no control is focused); the volume icon takes the mouse wheel. A blurred fade sits behind the floating bar. Unpin is gone from the bar; its right-most button is the picker. With nothing pinned there is no bar: the sidebar (and mobile menu) shows "Select player", which dispatches `open-player-panel` and opens the picker floating bottom right.

## Components
- `App\Livewire\PlayerBar` (`livewire/player-bar.blade.php`): a floating, rounded bar in the artwork's colors, one row: play/pause (in an accent derived from the cover by `App\Domain\Artwork\AccentColor`: a vivid `safe_colors` entry of another hue, else the complementary hue), previous/next, shuffle, repeat, elapsed/progress/total (the progress is the track's waveform, played part in the accent, when the playing track is in the library with an analysed own file: `PlayerBar::waveform()` looks it up like play history and remembers the result, a miss only 2 minutes; else a plain bar), volume, then artwork with title/artist/album, and on the right like (`like` capability, `toggleLike`), up next (`queue`: links to the device page), multiroom, the player picker, receiver (same tab, the cover and bar morph into the receiver via View Transitions; `np-cover` / `np-bar`, set up in the layout and `receiver.blade.php`) and unpin. Refreshes on MQTT push via `liveDevice(id)`; controls go through `SpotifyRouting::driverFor()` like `DeviceCard`. Narrow screens keep art, title and transport (`player-extra` / `player-progress` hidden).
- `<x-play-button>` (`components/play-button.blade.php`): replaces the old "button + `<x-device-picker>`" pair. When the pinned device is in the `devices` it was given (already filtered for what can play the item) it posts straight to `actionTemplate` with that id, plus a chevron (`elsewhere`, default on) that opens the picker; otherwise it opens the picker as before. The button's content is the slot, its classes the attributes.
- Used by albums (play, shuffle, track rows), artists, playlists, radio and "More on Spotify".
